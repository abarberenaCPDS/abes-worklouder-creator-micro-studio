# Agent guidance

- Targets deploy to macOS 13 and the package uses Swift tools 5.9. `AbesWorkLouderCreatorMicroStudio.xcodeproj` has the menu-bar app and standalone `Inspector` schemes; Studio hosts the shared Inspector view in its sidebar and embeds the separately permissioned Inspector utility for direct debugging.
- App UI/resources live in `Apps/`; shared HID, bridge, configuration, and integrations code plus tests live in the local Swift package `Packages/CreatorMicroStudioKit`.
- Verify with `swift test --package-path Packages/CreatorMicroStudioKit`, `xcodebuild -project AbesWorkLouderCreatorMicroStudio.xcodeproj -scheme CreatorMicroStudio -destination 'platform=macOS' build`, and the `Inspector` scheme when changing its standalone app.
- For one package test, add `--filter '<test-case-or-test-name>'` to the `swift test` command. Live tests against the device or Herdr are gated; only opt in deliberately with `CREATOR_MICRO_STUDIO_LIVE_TESTS=1`.
- The stock keymap fixture is a SwiftPM test resource; access it with `Bundle.module`, not a path relative to `#filePath`.
- `Pad.rows` is the firmware `[2, 4, 4, 3]` key matrix. UI drawings should use `Pad.physicalDisplayRows`, which also places the dial, joystick, and non-key case mark.
- Inputs are ids 0–19 (`Pad.configurableInputIDs`): keys 0–12, dial right 13 / left 14 / push 19, joystick up 15 / left 16 / down 17 / right 18. `KeymapManager` binds the dial push to `KV_OAI_AG19` (encoders[0][2]); AG19 is the last free id, so joystick diagonals and the centre press stay unsupported. Only keys 0–12 (`Pad.configurableActionKeyIDs`) have LEDs.
- Every input can use every `InputAction` (`KeyAction` is gone); defaults come from `InputAction.defaultAction(for:)` — keys Focus Agent (0–5 focus their Herdr slot, others the current agent), dial effort up/down and push Play/Pause, joystick model picker. Everything dispatches through `BridgeController.handleKeyPress` → `action(for:)`; never hard-wire an input id. Scroll, shortcut, media, voice and type-text need Accessibility. Actions and prompt text are host-side config and must never rewrite the device keymap.
- The Herdr command action (`InputAction.herdrCommand`) is a Herdr CLI line without `herdr`, run by `HerdrCommand`/`HerdrCLI` with an argument array (never a shell, never `command.invoke`); placeholders such as `{tab}` mean the *current* (focused) tab/workspace/pane, read fresh at press time. `{ask:…}` goes through `BridgeController.onAsk`, which the app wires to `HerdrAskPanel`. Only add an Examples entry whose syntax you checked against the local `herdr` usage text, offline.
- Permission UI: `InputMonitoringPrompt.request()` (in `Features/Permissions/PermissionHelper.swift`) asks, probes a listen-only event tap, and opens `PermissionHelperWindowController` (`.inputMonitoring` / `.accessibility`) when macOS shows nothing; reuse that helper and `AppIdentityCard` instead of adding separate "Open Settings" buttons. Launch requests stay quiet (`showHelperIfSilent: false`). Accessibility is named "Device Control and Data Access" on newer macOS; mention both names. HID report writes run on `WLDevice`'s private serial queue: never call `IOHIDDeviceSetReport` on main. Lighting saves after 3 s idle (preview paints are coalesced); Controls text saves on submit/blur/3 s idle.
- Persistent lighting is Studio-owned and lives in `config.json` `"lighting"` (`LightingPreferences`); all config writes go through `StudioConfigStore` (atomic, keeps unknown keys). The Inspector is temporary: what it paints lasts until Studio repaints, and only its Save to Studio buttons persist (into `"lighting"`). Studio calls `reloadConfiguration()` when it takes the pad back.
- The Welcome splash uses the `StudioAppIcon` image set (`StudioAppIconDev` in Dev builds), generated from the same Pure Pad + ABE'S bezel artwork as both app icons and website favicons. Run `scripts/update-icons.sh` after an intentional final artwork change so they stay in sync.
- To run the studio without hardware, set `WL_EMULATE=1` in the CreatorMicroStudio scheme's Run environment. The emulator is in that process; standalone Inspector still needs hardware.
- Bundle IDs use `dev.abeisonai.worklouder.*`; changing them resets macOS permissions such as Input Monitoring and Accessibility. Debug builds are the separate **Dev** app (`….creatormicrostudio.dev` / `….inspector.dev`, "… Dev" names, embedded helper `…InspectorDev.app` via the `$(WL_INSPECTOR_PRODUCT_NAME).app` embed reference, `AppIconDev`/`StudioAppIconDev` badged icons) so Xcode runs never touch the installed Release (**Stable**) app's grants, defaults or login item; per-configuration `WL_*` build settings feed Info.plist and `AppIdentity` reads them. Use `AppIdentity` instead of hard-coding app names, bundle IDs or the embedded Inspector path. Both channels share `~/.config/creator-micro-studio/config.json` and must not drive the pad at the same time.
- Hardware work needs macOS Input Monitoring for the specific app bundle and non-exclusive HID access. The sidebar Inspector shares Studio's process and grant; the embedded standalone Inspector helper has its own bundle ID and grant. Pause the Studio bridge before opening the standalone helper. Xcode Run schemes stop the other project app first; also quit Work Louder Input and Codex desktop because they can overwrite pad lighting. Firmware may return `{"ok":1}` for malformed writes, so verify LEDs/read back keymaps; keymap writes consume flash. See `docs/hacking.md` before changing the HID protocol.
- `scripts/update-icons.sh` regenerates the stable `AppIcon` and DEV-badged `AppIconDev` catalogs for both apps, the Welcome `StudioAppIcon`/`StudioAppIconDev` image sets, and website favicons from the shared artwork. `scripts/archive.sh` creates a signed Release archive; outputs are under ignored `.build/`.
